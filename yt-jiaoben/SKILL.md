# yt-jiaoben 脚本工程

## 概述

对**已立项选题**做脚本生产：**讲好商业故事**——输入契约校验 → 原爆点筛选（人拍板，开场候选过资格闸）→ 产前准备（B-Roll 清单+法律口径）→ A 稿纯口播故事稿（主产物）→ 降维修改 → 派生 B 稿三轨 → 硬指标扫描 → 人审 → 交付（A+B 双稿：飞书 doc + 本地存档 + 有限回填）。

核心原则：

1. **定义即法律**——好脚本标准见 `references/good-script-definition.md`（用户提供权威版）。模板和本文件与之冲突时，以定义为准。
2. **真实可考**——每个画面配公开凭证，禁伪现场感（HR-1/HR-5）；素材不够回 yt-ziliao 补搜，**脚本阶段禁止自己上网搜**。
3. **故事主线铁律**——现场冲突→戏剧反差→幕后动机→命运结局（writing-playbook §一）；财报/股权/数据只作背景道具，严禁作主线框架；叙事方法以 `references/writing-playbook.md` v0.4 为准。
4. **口播稿为主产物**——先写满 A 稿（纯口播，四幕完整，5600-8400 字），B 稿（三轨）从 A 稿逐段派生；禁止跳过 A 稿直接写三轨（v2.0"没有台词感"教训）。
5. **机器数指标，人拍创意**——A1-A6 硬指标机器强制（scan_script.py），原爆点 Top3/钩子方案/CTA/观点立场由人拍板。
6. **路径不硬编码**——token/ID/目录一律读 `config.yaml`（初始化时复制 config.template.yaml 填写），禁止缩写。

## 何时使用 / 不适用

| 场景 | 归属 |
|---|---|
| "给这个选题写脚本" / 选题已 confirmed 进入脚本阶段 | ✅ 本技能 |
| 选题还没立项（未过 C 闸门） | ❌ 先回 yt-fenxi |
| 资料报告缺失/完整度 <60 | ❌ 先回 yt-ziliao 补采 |
| 改脚本（人审反馈后修订） | ✅ 本技能（版本号 +1） |
| 剪辑/配音/字幕执行 | ❌ 人工或剪辑工具（本技能只出 brief 级标注） |

## 铁律（违反即返工）

- **禁编造**：事实/数据/引语/画面均无凭证不出场（HR-4/HR-5）；凭证格式 `[凭证 N] 引用+出处`。
- **禁越权写状态**：选题状态只读（config `state_readonly`），脚本写完**不改**选题状态（选题表无"脚本撰写"状态值，写即违规）。
- **空则填、不覆盖**：回填「脚本字数」等字段时已有内容绝不冲掉。
- **禁离场词**："以上就是本期全部内容/感谢收看/点赞关注/下期再见"——出现即硬拦截。
- **禁自我调研**：所有素材来自 yt-ziliao 报告 + yt-fenxi 分析卡；缺失→回 yt-ziliao 补采桥接。
- **开场 3 分钟禁财报**：股票代码/股权占比/财报术语出现在开场区段即硬拦截（scan）。
- **四层内容必标**：事实/争议/转述/观点——B 稿控制轨显式标 [内容层]，A 稿靠归属话术；全片 [观点] ≥1（HR-8）。
- **双语人名**：英文人名首次出现必须"中文译名（英文原名）"，后续统一中文简称。
- **token/ID 原样全文**：从 config.yaml 取，缩写必 400；回填字段前必须先 `+field-list` 查真实字段类型——字段名带"链接"≠URL 类型（实测「选题脚本链接」是 text，只收纯字符串；格式细节见 yt-ziliao/references/lark-field-formats.md）。
- **每次阶段跳转同步更新脚本文件头 `当前阶段` 字段**；断点恢复只读文件续跑。

## 执行流程

### 阶段 1：输入契约校验

读取 yt-fenxi 分析卡 N9 输出契约九字段（record_id/选题标题/选定切入角度含视角层/核心钩子/目标受众/反常识点清单/待验证项清单/资料采集链接/涉及敏感主体清单）。校验：
- 九字段齐全 + yt-ziliao 报告链接有效 + 报告完整度 ≥60 → 通过
- 缺项/完整度不足 → 报缺失清单，指明回 yt-fenxi 或 yt-ziliao，**终止不硬跑**
- config.yaml 缺失 → 从 config.template.yaml 复制，走初始化问答（池 token/存档目录/飞书文件夹/频道阶段）后重跑

**老选题 N9 契约补建（Step 0.5，必跑）**：N9 输出契约 2026-09-09 才建立，此前 confirmed 的老选题池记录必然缺字段（T-2026-008 实战踩过：跑到阶段 2 才发现契约不齐，只能停下来补）。此时**不停机硬跑、不跳过**：从 yt-fenxi 分析卡 + 池记录已有字段反推九字段，列出补建清单（字段名→取值来源→拟填值）找人确认后写入分析卡，再进阶段 2。补建本身不改选题方向，不触发重新立项。

### 阶段 2：原爆点筛选

按 `references/story-original-explosion.md` 执行：从 yt-ziliao 报告五个来源挖 5-10 个候选开场画面，**Step 1.5 先过开场资格闸**（必须是具体场景画面；财报/统计数据型移出开场表、转入"转"幕素材），五维评分（画面/冲突/基因揭示力/凭证/代入），≥4.0 进 Top3 备选。**铁律 2 前置**：无凭证候选直接淘汰不参评。Top3 + 落选理由（50-100 字/个）呈人拍板。

### 阶段 3：产前准备

1. **B-Roll 清单**（quality-hardrules.md §二）：视觉轨需求逐条落清单（时间码/画面/类型/来源/状态），yt-ziliao 报告内素材优先，报告外标"自行获取+合法途径"，拍摄前销号。
2. **法律口径预审**（§三）：消费 fenxi 敏感主体清单，六口径逐项过；涉敏感主体台词标 `[法审]`；结论三态（通过/修改后通过/不通过），写入交付物 Part 2。机器只标雷区不排雷，人终审。

### 阶段 4：A 稿写作与降维修改（writing-playbook v0.4 工序）

按 `references/script-template.md` 产出结构，按 `references/writing-playbook.md` 施工。**A 稿是主产物，先写满；B 稿后置派生。**

1. **元数据头**（含故事主线一句话 + 核心争议点）+ 三视角检查
2. **素材卡片化 + 四幕卡槽归类**（writing-playbook §三）：素材→单点卡片（一张一事带来源），强行归入起/承/转/合卡槽——卡槽逻辑不通顺前不写连接词
3. **逆向出稿**（§三）：终极 Payoff → 前置条件 → Hook → 中场连线；承→转之间架**因果桥梁句**
4. **A 稿骨架稿**：纯口播故事稿，四幕分节，每幕尾黑体锚定观点；总字数 5600-8400（280 字/分 × 时长 ±10%）
5. **删减轮 + 朗读轮**：砍偏离主线干货 ≥15% 压到目标字数 → 朗读拆句 ≤20 字；**冷却 ≥24h/人审间隔一晚**（同会话不得连续两轮改稿，跨会话断点续跑）
6. **派生 B 稿**（双轨轮）：从 A 稿逐段配三轨——听觉（停顿重音符号、SEO 词）+ 视觉（客观动作、B-Roll 编号、时长估算）+ 控制（情绪、拍点、**[内容层]四层标注**、凭证、可砍级）
7. 情绪曲线按事实梯度法（§二）：L1-L4 逐步释放；中段（3000-5000 字）凭证 <2/千字 = 塌陷，补或砍
8. 钩子按 `references/hook-retention-playbook.md` 五变体选 3 种出**三版对比表**（频道阶段决定开放范围）；rehook 每 2-3 分钟、手法轮换；视觉轨画面按 `references/material-to-visual.md` 五类转换表写，同步生成 B-Roll 清单行

### 阶段 5：质量闸门

1. `python3 scripts/scan_script.py <交付物.md> --duration <分钟>`——A 稿区跑 A1/A4/A6/开场财报闸/人名/金句，B 稿区跑 A2/A3/A5/四层标注，硬拦截全部清零
2. 软维度评分（原爆点五维 + 划停力 + 赛道契合，0-100）+ **预期留存档位标注**（B1/B2/B3 对应档，标注"未经实证，待 fupan 校准"）

### 阶段 6：人审与交付

人审（硬闸门）：展示评分表+扫描报告+待决策项（开场画面/钩子变体/法审结论），等明确拍板。通过后：
- 飞书 doc：按 script-template.md §四 交付物结构建文档（含 Part 3a A 稿 + Part 3b B 稿；标题白名单清洗后 create，见 write 规范），存入 config `doc.folder_token`
- 本地存档：`paths.output_dir/<选题编号>-v<版本>-A.md` 与 `<选题编号>-v<版本>-B.md`
- 回填：「脚本字数」空则填不覆盖；状态**不动**
- 汇报：一句话交付摘要 + 预期留存档位 + 待 fupan 校准项

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 资料不够就自己上网搜 | 回 yt-ziliao 补采桥接；脚本阶段零自研 |
| 画面写"气氛紧张/十分愤怒" | 写客观动作："他把手中的笔放下，三秒没有说话" |
| 跳过 A 稿直接写三轨 | 先写满 A 稿纯口播（v2.0 教训：三轨并列写 → 口播只剩骨架 1130 字/24 分钟） |
| 让财报/股权当主线框架 | 主线=现场冲突→戏剧反差→幕后动机→命运结局；财报只在"转"幕作解谜答案 |
| 写完把选题状态推到"脚本撰写" | 状态只读；池里没这个选项，写即越权 |
| CTA 三件套全要 | 单一动作：跳推荐视频（连续观看优先） |
| 用"我觉得/大家都知道"增强说服力 | 数据+引语；观点必标归属+论证链（HR-8 四层标注） |
| 金标准锚点空着就不管评分 | 锚点未建期，评分旁强制标"未经实证"；锚点建成后重评 |
| 风格靠 AI 默认输出 | 每期记录 3 个风格决策（runtime/style-log.md），3-5 期后固化 voice-profile |
| 人审说"感觉不对"就全文重写 | 先查 writing-playbook §五 反馈翻译表，只改诊断出的结构位置 |

## 修改轮次规则

1. **轮次定义**：每次用户给出反馈并等待新稿 = 一轮；总上限 3 轮
2. **人机分工**（意图/技术双轴，writing-playbook §四）：用户只能改**观点/故事走向/语气风格**；结构/节奏/指标层（拍点/视听比/字数/事实梯度）归 AI，用户只验收——防止改 A 坏 B
3. **版本管理**：每轮定稿存独立文件 `runtime/.drafts/<选题编号>-v<N>.md`，不覆盖；"回到 v2" = 拿 v2 文件继续改，禁止凭记忆重写
4. **3 轮后仍不满意 → 停止改稿**，回 yt-fenxi 重评选题角度（是切入角度的问题，不是执行的问题），不继续磨稿

## 风格演化机制（从零起号的风格策略）

频道从零开始，**不预设风格，用演化日志让风格自然涌现**：

1. **每期定稿时**（Step 13 内）：记录 ≥3 个风格决策——这期钩子为什么选这个变体？为什么某段语速/情绪这样处理？为什么用这个转折句型而不是那个？写入 `runtime/style-log.md`（一期一节，含日期/选题编号/决策+一句理由）
2. **每期交付时**：风格对照检查——数"标准 YouTube 腔"占比（"大家好""今天我们来聊聊""让我们一起来看看"类句式），>30% 警告并在 style-log 记一笔
3. **3-5 期后**：回读 style-log，重复 ≥3 次的同类决策 = 风格雏形，固化为 `references/voice-profile.md`（常用句型/禁忌词/节奏偏好/叙事惯用路径），此后写脚本前强制读取
4. **原则**：风格是复盘出来的，不是设计出来的；v0 期宁可结构对但声音平，也不硬凹人设

## 发布后校准机制（第一期起生效）

每期发布后 48 小时-1 周内执行（数据源：fupan 技能或人工截图 YouTube Studio）：

1. **拉数**：前 30 秒留存率、AVP、相对留存曲线的掉粉点时间戳
2. **对照**：把本期软维度评分与真实留存对比——评分高但留存差的环节，找脚本文本原因（铺垫超长？拍点失效？视听比失衡？）
3. **修正**：小偏差记 style-log；同一偏差出现 ≥2 期 → 升级（改 config 参数或把软建议升为硬指标）
4. **锚点**：第 1 期发布后即把本期脚本+真实留存数据注册为首个金标准锚点（`references/gold-standard-anchors.md` 建表），此后每期与锚点对比评分
5. **节奏**：3-5 期后输出一次校准报告（哪些参数改了、依据是什么），经人确认后固化进 config.template
