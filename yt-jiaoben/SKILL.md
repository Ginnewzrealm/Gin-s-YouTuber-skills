# yt-jiaoben 脚本工程

## 概述

对**已立项选题**做脚本生产：输入契约校验 → 原爆点筛选（人拍板）→ 产前准备（B-Roll 清单+法律口径）→ 四模块三轨装配 → 硬指标扫描 → 人审 → 交付（飞书 doc + 本地存档 + 有限回填）。

核心原则：

1. **定义即法律**——好脚本标准见 `references/good-script-definition.md`（用户提供权威版）。模板和本文件与之冲突时，以定义为准。
2. **真实可考**——每个画面配公开凭证，禁伪现场感（HR-1/HR-5）；素材不够回 yt-ziliao 补搜，**脚本阶段禁止自己上网搜**。
3. **工程化交付**——三轨制（听觉/视觉/控制），画面描述 100% 客观动作，剪辑师零沟通成本可执行。
4. **机器数指标，人拍创意**——A1-A6 硬指标机器强制（scan_script.py），原爆点 Top3/钩子方案/CTA 由人拍板。
5. **路径不硬编码**——token/ID/目录一律读 `config.yaml`（初始化时复制 config.template.yaml 填写），禁止缩写。

## 何时使用 / 不适用

| 场景 | 归属 |
|---|---|
| "给这个选题写脚本" / 选题已 confirmed 进入脚本阶段 | ✅ 本技能 |
| 选题还没立项（未过 C 闸门） | ❌ 先回 yt-fenxi |
| 资料报告缺失/完整度 <60 | ❌ 先回 yt-ziliao 补采 |
| 改脚本（人审反馈后修订） | ✅ 本技能（版本号 +1） |
| 剪辑/配音/字幕执行 | ❌ 人工或剪辑工具（本技能只出 brief 级标注） |

## 铁律（违反即返工）

- **禁编造**：事实/数据/引语/画面均无凭证不出场（HR-4/HR-5）；凭证格式 `[凭证 N] 引用+出处`。
- **禁越权写状态**：选题状态只读（config `state_readonly`），脚本写完**不改**选题状态（选题表无"脚本撰写"状态值，写即违规）。
- **空则填、不覆盖**：回填「脚本字数」等字段时已有内容绝不冲掉。
- **禁离场词**："以上就是本期全部内容/感谢收看/点赞关注/下期再见"——出现即硬拦截。
- **禁自我调研**：所有素材来自 yt-ziliao 报告 + yt-fenxi 分析卡；缺失→回 yt-ziliao 补采桥接。
- **token/ID 原样全文**：从 config.yaml 取，缩写必 400；URL 字段写 `{text, link}` 对象 text 在前（见 yt-ziliao/references/lark-field-formats.md）。
- **每次阶段跳转同步更新脚本文件头 `当前阶段` 字段**；断点恢复只读文件续跑。

## 执行流程

### 阶段 1：输入契约校验

读取 yt-fenxi 分析卡 N9 输出契约九字段（record_id/选题标题/选定切入角度含视角层/核心钩子/目标受众/反常识点清单/待验证项清单/资料采集链接/涉及敏感主体清单）。校验：
- 九字段齐全 + yt-ziliao 报告链接有效 + 报告完整度 ≥60 → 通过
- 缺项/完整度不足 → 报缺失清单，指明回 yt-fenxi 或 yt-ziliao，**终止不硬跑**
- config.yaml 缺失 → 从 config.template.yaml 复制，走初始化问答（池 token/存档目录/飞书文件夹/频道阶段）后重跑

### 阶段 2：原爆点筛选

按 `references/story-original-explosion.md` 执行：从 yt-ziliao 报告五个来源挖 5-10 个候选开场画面，五维评分（画面/冲突/基因揭示力/凭证/代入），≥4.0 进 Top3 备选。**铁律 2 前置**：无凭证候选直接淘汰不参评。Top3 + 落选理由（50-100 字/个）呈人拍板。

### 阶段 3：产前准备

1. **B-Roll 清单**（quality-hardrules.md §二）：视觉轨需求逐条落清单（时间码/画面/类型/来源/状态），yt-ziliao 报告内素材优先，报告外标"自行获取+合法途径"，拍摄前销号。
2. **法律口径预审**（§三）：消费 fenxi 敏感主体清单，六口径逐项过；涉敏感主体台词标 `[法审]`；结论三态（通过/修改后通过/不通过），写入交付物 Part 2。机器只标雷区不排雷，人终审。

### 阶段 4：脚本装配

按 `references/script-template.md`：
1. 元数据头九字段 + 三视角检查
2. 四模块骨架（Hook ~1min / 主体 6-8 子节点 ~23min / 高潮 ~3min / 无缝 CTA ~1min；20-30 分钟档总字数 5600-8400）
3. 三轨正文：每段听觉（台词≤20 字/句、音效、SEO 词）+ 视觉（客观动作、B-Roll 编号）+ 控制（情绪、拍点、凭证）
4. 钩子从 `references/hook-retention-playbook.md` 五变体选（频道阶段决定开放范围）；rehook 每 2-3 分钟一次、手法轮换；子节点按"次好点第一"排序

### 阶段 5：质量闸门

1. `python3 scripts/scan_script.py <脚本> --duration <分钟>`——硬拦截全部清零
2. 软维度评分（原爆点五维 + 划停力 + 赛道契合，0-100）+ **预期留存档位标注**（B1/B2/B3 对应档，标注"未经实证，待 fupan 校准"）

### 阶段 6：人审与交付

人审（硬闸门）：展示评分表+扫描报告+待决策项（开场画面/钩子变体/法审结论），等明确拍板。通过后：
- 飞书 doc：按 script-template.md §四 交付物结构建文档（标题白名单清洗后 create，见 write 规范），存入 config `doc.folder_token`
- 本地存档：`paths.output_dir/<选题编号>-v<版本>.md`
- 回填：「脚本字数」空则填不覆盖；状态**不动**
- 汇报：一句话交付摘要 + 预期留存档位 + 待 fupan 校准项

## 数据契约

| 项 | 约定 |
|---|---|
| 输入 | yt-fenxi N9 九字段 + yt-ziliao 报告 URL + 完整度 ≥60 |
| 时长档 | 只保留 20-30 分钟一档（拍板）；字数 5600-8400（280 字/分 ±10%） |
| 输出 | 飞书 doc（结构见模板 §四）+ 本地 md 存档 + 脚本字数回填（空则填） |
| 下游 | fupan 消费：段落时间码坐标（留存掉粉点映射用）；制作四件套消费：B-Roll 清单+分镜 |
| 校准 | 发布后 B1-B3 回流，滚动修正 wpm_anchor/软维度权重/子节点配比（记入 config 变更历史） |

## 依赖

| 技能 | 强度 | 说明 |
|---|---|---|
| yt-fenxi | 硬依赖（输入） | 消费 N9 输出契约；法审不通过时退回它重评 |
| yt-ziliao | 软依赖（凭证） | 素材缺口回它补采；桥接失败时本次脚本只能写到"凭证齐"为止 |
| lark-doc / lark-base | 硬依赖（交付） | 建飞书文档/回填字段，经 Skill() 调用不直连 API |

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 资料不够就自己上网搜 | 回 yt-ziliao 补采桥接；脚本阶段零自研 |
| 画面写"气氛紧张/十分愤怒" | 写客观动作："他把手中的笔放下，三秒没有说话" |
| 写完把选题状态推到"脚本撰写" | 状态只读；池里没这个选项，写即越权 |
| CTA 三件套全要 | 单一动作：跳推荐视频（连续观看优先） |
| 用"我觉得/大家都知道"增强说服力 | 数据+引语；观点必标归属方 |
| 金标准锚点空着就不管评分 | 锚点未建期，评分旁强制标"未经实证"；锚点建成后重评 |
