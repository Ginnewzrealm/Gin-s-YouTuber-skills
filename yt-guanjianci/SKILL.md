# yt-guanjianci 关键词+标题库

## 概述

**服务性技能**（被调用为主，不直接被人触发）：输入词根/选题 → 按四层方法论产出**关键词包+标题矩阵** → 机械闸过检 → 落盘 core 共享工作区 `关键词库/` → 消费方各取所需。同时维护**频道词库**（句式/钩子词累积+CTR 验证回流），是整个链路的上游资产。

核心原则：

1. **方法论有出处，公式按库匹配**——评估用四级分级（references/keyword-grading.md），扩展用四维算子（longtail-matrix.md），标题用 4 公式+两阶段策略（title-formulas.md），竞品句式用三元拆解（reverse-engineering.md）。**禁止凭感觉造标题**。
2. **档位诚实标注**——A=精确数据/B=相对指数/C=手工定性；C 档分级须人复核，机器不得把定性值说成精确值。
3. **一次调用三层全出**——关键词包（JSON 落盘）+标题矩阵（内存直出）+库累积（追加）。tansuo 只读搜索量层，fenxi 读+标题预判，发布全吃。
4. **保鲜靠 fupan**——关键词 30 天/竞品 7 天重扫，挂 fupan 复盘时顺手刷新；过期词禁用（AMD 教训：老词 CTR 1.8% 被断流）。

## 何时使用 / 不适用

| 场景 | 归属 |
|---|---|
| tansuo 入池前：这个领域什么词有人搜 | ✅ 本技能（被调） |
| fenxi 立项时：标题预判+搜索量验证 | ✅ 本技能（被调） |

## 执行流程

### 步骤 1：定词根与档位

读调用方输入（tansuo=领域词 / fenxi=选题标题 / 发布=核心钩子）。查 config 数据源档位：
- A 档：DataForSEO 精确值（须配 key）
- B 档：Google Trends `gprop:youtube` 相对指数，对标基准词换算量级
- C 档（默认）：竞品扫描+定性分级，**输出标注"须人复核"**

### 步骤 2：产关键词包（按 keyword-grading.md + longtail-matrix.md）

1. 四维算子扩展长尾（A 动作/B 冲突/C 疑问/D 时间，各 2-3 条）
2. 四级分级（大/中/小/微长尾）+KD 判定（新频道主选 KD<20 小词）
3. 意图三分：信息型才进长视频选题池；交易型转信息型再收
4. 组装 JSON：`{词根, 查询时间, 数据源档位, 主关键词{词,分级,月搜索量,竞争度}, 次级关键词[], 长尾词[], 竞品标题用词, 标题矩阵[], 验证记录[]}`

### 步骤 3：产标题矩阵（按 title-formulas.md + reverse-engineering.md）

- **≥3 候选**：钩子词×句式矩阵生成，每条标 `{候选, 公式, 适用阶段(冷启动/推荐期/通用), 钩子词, 句式, 实体词}`
- 冷启动候选：公式二/四/五为主，含长尾词，标准主谓宾
- 推荐期候选：公式一/三/六为主，高情绪 Hook
- 每条过机械规范：**8-35 字 / 禁逗句号叹号 / 无占位符**；关键词前 20 字；阿拉伯数字
- **封面词 2-4 个**：从钩子词按五大情绪抓手（含决策考古类）+三组合公式提炼（references/thumbnail-words.md），每个 ≤6 汉字，单独可输出供缩略图叠字

### 步骤 4：机械闸

`python3 scripts/keyword_brief.py <关键词包.json>`：schema 齐/档位合法/标题规范。exit 1 → 回步骤 2 修正。

### 步骤 5：落盘与累积

- 关键词包存 `关键词库/<词根>-keywords.json`；频道词库累积更新 `关键词库/频道词库.json`（句式库/钩子词库/验证记录追加）
- 输出给调用方：tansuo 取分级+搜索量；fenxi 取前 3 标题做预判；发布取全部候选+关键词包喂 agrici

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 拿 Google 搜索量当 YouTube 搜索量 | 无站内量接口；B 档 Trends 相对值/C 档定性，档位必须标 |
| 新频道抢大词 | 大词仅作 Tag；主选 KD<20 的小词/微长尾 |
| 凭感觉写标题不进矩阵 | 必须钩子词×句式矩阵产出，公式来自库 |
| 冷启动用高情绪标题 | 0-14 天搜索匹配优先；14 天后才换推荐期标题 |
| 换标题超 2 次 | 换后 48-72h 算法重评估，≤2 次 |
| 把 C 档定性值写成精确月搜索量 | C 档输出必须带"定性·须人复核"标注 |
