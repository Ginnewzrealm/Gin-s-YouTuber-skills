# 搜索与资料梳理策略

## 一、搜索分工

### 子 Agent 配置

| Agent | 范围 | 关键词语言 |
|-------|------|-----------|
| 中文搜索 | 微博、知乎、百度、36氪、贴吧、豆瓣 | 中文 |
| 英文搜索 | BBC、NYT、Reddit、Hacker News、Medium | 英文 |
| 官方/学术 | 政府公告、arXiv、Google Scholar、行业报告 | 中英双语 |
| 视频（可选） | B站、YouTube | 中文为主 |

每个 Agent 目标：≥20条有效资料，合计 ≥60条。

> **注意**：20 条/Agent 和 60 条合计是**努力目标**，不是硬性阻断条件。单 Agent 未达 20 条时继续流程，最终以综合完整度评分（D1-D7）和精选分布约束为质量门。

### 联网指引

> **OpenCLI 优先，WebSearch/WebFetch 降级**
>
> 凡是需要通过浏览器访问的平台或 URL，一律先尝试 OpenCLI：
> 1. 有 OpenCLI 站点适配器的平台（知乎、微博、B站、YouTube、Reddit 等）→ 调用对应适配器搜索
> 2. 无适配器或适配器失败 → 使用 `opencli browser` 通用命令打开并提取页面
> 3. OpenCLI 完全不可用（未安装、桥接失败、超时）→ 降级到 **WebSearch** 发现来源 → **WebFetch** 定向提取详情
>
> 多次搜索多组关键词，一手来源优于二手
> 记录：标题、URL、来源平台、发布日期

### OpenCLI 使用规范

- 站点适配器命令（如 `youtube search`）带 `--window background --keep-tab false`，后台运行并防止标签堆积
- `browser open/extract` 等浏览器子命令**不带** `--keep-tab false`（该参数不被支持），由 `scripts/opencli_adapter.py` 统一解析返回的 `page` targetId 并在提取后调用 `browser tab close` 清理
- 浏览器相关操作统一通过 `scripts/opencli_adapter.py` 封装层调用，避免主流程直接操作 shell
- 子 Agent 只负责生成搜索词和 URL 列表，不直接操作浏览器开关
- 主流程统一完成浏览器就位、OpenCLI profile 切换、连接探测和善后清理
- OpenCLI 失败时记录失败原因，自动降级，不在单平台死磕

## 二、关键词矩阵（搜集前设计）

按"维度 × 语言"设计，每行含 ≥3 中文 + ≥3 英文，差异 ≤1：

| 维度 | 中文关键词 | 英文关键词 |
|------|---------|---------|
| 人物 | 戴威、ofo创始人 | Dai Wei, ofo founder |
| 产品 | ofo、小黄车、共享单车 | ofo, bike-sharing, dockless bike |
| 事件 | 押金危机、倒闭、债务 | deposit crisis, collapse, debt |
| 组织 | 滴滴、阿里、朱啸虎 | Didi, Alibaba, Zhu Xiaohu |
| 行业 | 共享经济、单车、押金 | sharing economy, VC,押金 |
| **历史沿革**（D7 原料，必配） | **主体全名 + 成立/创办时间、收购/合并史、升格/升级节点、冠名/合作、创始人/历任掌门、注册资本/股权** 例："China GT 成立 2016""中视甲子 注册资本""力盛 收购 擎速""邓大为 创办" | **主体英文名 + founded/established, acquisition, merger, history, CEO founder** |

> **历史沿革词规则**：矩阵每行 ≥3 词差异 ≤1 的约束对历史沿革行同样适用；该行的词直接决定 D7 历史脉络覆盖度，漏配会导致完整度评分卡壳。

## 三、去重策略

### 阶段一（搜集层面）
- 每个子 Agent 内部：URL 去重 + 标题相似度 >80% 去重

### 阶段二（中央合并层面）
- 所有子 Agent 结果汇总到中央合并节点
- 全局去重：URL 完全一致，或标题相似度 >85%
- 去重后剩余条目再进入可信度评分和精选

### 阶段三（整理层面）
- 按事件聚类，同事件保留最权威 ≤3 条
- 淘汰的保留在全量索引，不进精选

## 四、信息完整度评分

| 维度 | 计算 | 满分 | 阈值 |
|------|------|------|------|
| D1 平台覆盖 | 有素材的平台类型数 ÷ 5 × 100 | 100 | ≥60 |
| D2 语言覆盖 | min(zh%, en%) - \|zh%-en%\|×0.3 | 100 | ≥60 |
| D3 来源类型 | 不同类型数 ÷ 3 × 100 | 100 | ≥60 |
| D4 立场覆盖 | min(支持,质疑,中立) ÷ 5 × 100 | 100 | ≥60 |
| D5 时间分布 | (1 - 熵/最大熵) × 100 | 100 | ≥60 |
| D6 URL覆盖率 | 有URL的信源数 ÷ 总数 × 100 | 100 | ≥95 |
| D7 历史脉络 | 标题/摘要命中历史节点词（成立/收购/升格/冠名/创始人等）的素材数 ÷ 总数 × 100 | 100 | ≥40 |

**综合评分 = (D1+D2+D3+D4+D5+D6+D7) ÷ 7**

> D7说明：历史节点词表内置于 `scripts/score_materials.py` 的 HISTORY_MARKERS。纯当下型选题（无历史主体）天然偏低，靠补搜动作表里的沿革词补齐；确实无史可考的选题由用户豁免。D7 是下游 xuanti-fenxi"深度揭示力"评分的原料维度。

| 评分 | 处理 |
|------|------|
| ≥80 | ✅ 通过 |
| 60-79 | ⚠️ 补搜（见§五补搜动作表） |
| D6<95% | 🔴 直接降级pending，不补搜 |

> D5说明：熵= -Σp_i×log(p_i)，p_i=第i月素材数÷总素材数。分布越均匀熵越高，D5越接近100。

## 五、补搜动作表

| 不达标维度 | 补搜动作 |
|-----------|---------|
| D1 平台覆盖 | 缺中文平台→追加知乎/微博搜索；缺英文平台→追加Reddit/Hacker News；缺视频→追加B站/YouTube；缺官方→追加政府网站/公司官网 |
| D2 语言覆盖 | 中文不足→追加中文关键词（人物/事件/行业各5个）；英文不足→追加英文关键词（人物英文名/行业术语/事件英文名） |
| D3 来源类型 | 缺官方发布→追加"官方声明"/"政策文件"搜索；缺学术→追加arXiv/Google Scholar；缺视频内容→追加B站/YouTube |
| D4 立场覆盖 | 缺支持方→搜索"XX积极评价/正面影响/优势"；缺质疑方→搜索"XX问题/争议/批评/风险"；缺中立→搜索"XX分析/解读/客观报道" |
| D5 时间分布 | 缺早期→追加历史时间点搜索（如"2020XX"）；缺近期→追加近3个月关键词；缺中间段→补漏月份关键词 |
| D7 历史脉络 | 补搜主体沿革词：`<主体> 成立/创办/首届`、`<主体> 收购/合并/股权/注册资本`、`<主体> 升格/升级/冠名/签约`、`<创始人> 创办/历任`（例词见 §二 历史沿革行） |

**补搜执行流程**：
1. 根据不达标维度选择对应补搜动作
2. 追加专门的搜索Agent或关键词
3. 重新收集 ≥20条 后重新计算完整度评分
4. 仍不达标则写入 supplement_suggestion，可选用户豁免

## 六、资料标注规范

### 字段

每条资料：类型 | 权威性 | 核实状态 | 立场 | 摘录要点

### 类型

新闻报道（权威媒体原创）/ 新闻报道（自媒体转载）/ 官方发布 / 社交媒体 / 论坛 / 视频 / 公众号 / 知乎 / 学术论文 / 行业报告

### 权威性

- **高**：官方发布、权威媒体原创报道、学术论文、行业报告
- **中**：一般媒体、知名自媒体、知乎高赞
- **低**：匿名来源、论坛匿名帖

### 核实状态

- **多方证实**：≥2独立来源交叉印证
- **单一来源**：仅一来源报道
- **存疑待核实**：信息矛盾或可信度存疑

### 立场

- **支持方** / **质疑方** / **中立**

### 可信度分

```
可信度分 = 权威性权重分×40% + 核实状态分×40% + 新鲜度分×20%
```

| 权威性 | 分值 | 核实状态 | 分值 | 新鲜度 | 分值 |
|--------|------|---------|------|--------|------|
| 高 | 100 | 多方证实 | 100 | ≤7天 | 100 |
| 中 | 70 | 单一来源 | 60 | ≤30天 | 80 |
| 低 | 40 | 存疑 | 30 | ≤90天 | 60 |
| | | | | >90天 | 40 |

## 七、精选分布约束

**精选30-80条，分布约束**：

| 约束 | 限制 |
|------|------|
| 高权威+多方证实 | ≥30% |
| 中权威+单一来源 | ≤40% |
| 低权威+单一来源 | ≤15% |
| 低权威+存疑 | ≤5% |
| 平均可信度分 | ≥70 |

**冷门领域兜底**：<10条时高权威+多方证实下限降至20%，<5条时降至10%。

**超标处理**：优先补搜 → 降权移至全量索引 → 豁免（用户声明后）

## 八、评分脚本

可信度分、D1-D7 完整度评分、精选分布约束检查，统一调用：

```bash
python3 scripts/score_materials.py <materials.json>
```

输入 `materials.json` 需包含 `topic` 和 `items` 数组，每个 item 至少包含：
- `title`, `url`, `platform`, `language`, `publish_date`
- `type`, `authority`, `verification`, `stance`

脚本输出完整度评分、精选结果、分布约束检查、补搜建议。

## 九、搜不到的处理

尽力后仍无法获取的平台，报告中标注：
> ⚠️ [平台名]内容未能充分获取

不要死磕，搜2-3轮无果即标注。
