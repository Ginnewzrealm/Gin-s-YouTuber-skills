# 资料汇总分析报告模板

> 严格按此模板输出，不随意增删章节。

## 写作原则

1. **事实和观点严格分开**：事实标注核实状态，观点标注立场
2. **不编造**：搜不到标注「暂缺」，不确定标注「存疑」
3. **每个事实陈述附来源链接**
4. **摘录用概括不用评价**："这篇说了什么"而非"这篇好不好"
5. **切入视角建议务实**：推荐可执行、成功率高的角度

## 英文素材翻译规则

报告主体中文。英文素材**不翻译**，仅转述框架：
- 人名/时间/数字/金额：保留原文
- 机构名：中文翻译+英文原文 (SEC)
- 报告/文献标题：保留英文原文
- 事件名：中文翻译+英文原文 (regulatory overhaul)

## 绝对禁区

❌ 套话："首先...其次...最后"、"综上所述"
❌ 空洞词："赋能"、"抓手"、"打造闭环"
❌ 教科书开头："在当今AI快速发展的时代"
❌ 踩雷词："说白了"、"意味着什么"、"本质上"
❌ 空泛工具名：要说具体名字，不说"AI工具"

## [待核实] 自检规则

**在写入飞书文档之前必须执行**。

### 一、事实核查

1. 逐章扫描：提取具体数字、人名、时间、机构名、金额
2. 逐条核对：是否有来源链接？
3. 强制标注：无链接的追加 `[待核实]`
4. 生成清单：汇总所有待核实项

### 二、质量检查（交付前必须逐项确认）

- [ ] 中英文信息源都有
- [ ] ≥5 种平台类型
- [ ] 不同立场都有（支持/质疑/中立）
- [ ] 完整度评分 ≥80（D6≥95% 直接降级 pending，不补搜）
- [ ] 精选可信度分 ≥70
- [ ] 每条标注：类型、权威性、核实状态、立场
- [ ] 事实与观点分开
- [ ] 争议点原料已显式配对（3.5），双方主张+来源+可裁决性齐全，无倾向判断
- [ ] 六章齐全，格式符合本模板
- [ ] 精选 30-80 条
- [ ] 切入视角基于素材务实推荐
- [ ] 无触犯绝对禁区
- [ ] 无编造信息
- [ ] 事实陈述有来源链接

### 三、待核实清单持久化

自检生成的待核实清单必须同时保存到：

```text
runtime/.verification/<topic>.json
```

结构示例：
```json
{
  "topic": "萝卜快跑在武汉运营",
  "generated_at": "2026-07-19T...",
  "items": [
    {
      "text": "2024年Q3营收达15亿美元",
      "chapter": "二、已确认事实",
      "source_url": null,
      "status": "open"
    }
  ]
}
```

**交付格式**：
```
⚠️ 以下信息需要人工确认（共N条）：
  - "2024年Q3营收达15亿美元" — 来源：[链接]
  - "涉及XX公司CTO张三" — 来源：[链接]
```

**禁止**：
- ❌ 因"看起来合理"跳过标注
- ❌ 把单一来源数字当事实
- ❌ 说"基本确认"——要么确认，要么待核实
