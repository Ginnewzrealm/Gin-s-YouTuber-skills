# 商业拆局选题挖掘手册 v2（三层颗粒 × 五维信源 × 检索语法）

> 来源：2026-09 归档三份材料整合——《互联网商业"极境考古"挖掘操作手册》《经营者/产品微观颗粒打法》《Agent 专用执行手册（ROLE/五维）》。
> 适用：**商业拆局类选题**（公司/人物/产品拆解——新频道定位）。非此类选题仍走通用六章 + search-strategy.md。
> 定位：本手册是"**怎么挖**"的地图，挂在步骤 5 搜索环节。六章报告骨架不变——挖到的料按"六、归位映射"落回原章节。
> 采集层纪律不变：只挖掘、记录、整理；不归纳论点、不推荐角度、不推导投资结论。

## 〇、约束条（五条，违反即返工）

1. **禁用主观定性词**："具有远见卓识""管理层经验丰富""产品体验优秀"类表述一律禁止。写事实，不写评语。
2. **每条标信源类型**：司法裁判文书 / 工商变更记录 / 早期应用商店 Changelog / 做空报告 / 招股书附注……让读者一眼知道这是哪类证据。
3. **锚定可追溯证据**：所有陈述必须落到具体来源（URL/文书号/存档链接）；搜不到标「暂缺」，不确定标「存疑」。不编造。
4. **五维封闭 + 推导不越界**：采集只落五个维度（见下），不得发散；**维度五 b（Kill_Thesis 反向假设推导）归 yt-fenxi**——本技能只交空方证据包，不做"如果市值蒸发 50%"的推导。
5. **归因纪律**：早年经历/原生家庭与后来行为的关联，只记录"存在耐人寻味的呼应"级事实并附双方证据；**不得写成心理诊断**（❌"他因为童年缺爱才独裁" / ✅"早年经历与后来的 X 存在耐人寻味的呼应，当事人自述…，离职者回忆…"）。心理动因的最终解读归 jiaoben 叙事层且须经人审。

## 二、人（经营者 + 团队）

### 维度一：经营者考古（Founder & Management Archetype）

**目标**：撕掉公关人设和"成功后写的自传"，还原最真实的性格底色、信念、决策盲区与真实反应。

**信源**：Wayback Machine 早期个人博客/公司官网 About Us ｜ 早期论坛与社交账号（贴吧/雪球早期/V2EX/知乎早期/Twitter 历史回复）｜ 工商变更记录 ｜ 裁判文书 ｜ 离职员工审计（脉脉/Glassdoor/Reddit r/company review/小红书）。

**检索语法**：

```
site:xueqiu.com "创始人姓名" filetype:html
site:v2ex.com/t/ "创始人用户名"
"创始人姓名" AND ("内部信" OR "演讲全文" OR "早年" OR "高考" OR "第一次创业" OR "离职")
site:maimai.cn "公司名" ("CEO" OR "老板" OR "脾气" OR "加班" OR "管理风格")
site:36kr.com "公司名/产品名" "上线"   ← 限定创立前 2 年，找种子期痕迹
```

**微观打法三个采集点**（怎么挖 → 为什么 → 纪律）：

1. **早期心理补偿线索**：搜 10-20 年前籍籍无名时的言论、早年创业失败记录、求学背景。→ 极境下的偏执与掌控欲往往能在早年挫折中找到"根源代码"。→ **纪律：只记录可考证的早年事实与当事人自述，呼应式呈现，不做心理诊断**（约束条 5）。
2. **生死压力测试**：通过裁判文书、离职高管爆料、濒临倒闭时的媒体暗访，采集"现金只够发一个月工资/核心高管集体出走/遭恶意做空"时他**第一时间做出的具体动作**（甩锅还是扛责、保全自己还是保护股东）。→ 顺境中的领导者都是哲学家，绝境中的微观动作才检验契约精神。→ **只记录动作与多方说法，不评道德**（那是 fenxi/jiaoben 的活）。
3. **权力结构**：查早期工商变更、股权代持、离职联合创始人访谈。→ 查清早期谁出局、为什么出局，团队权力分配与容人尺度自然显形。

### 维度四：早期投资人投后复盘（Early Investor Due Diligence）

**目标**：拿到对赌真相与"当时被掩盖的致命短板"。

**信源**：早期天使/A 轮投资人在播客、公开访谈、投资笔记中的复盘分享。

**采集点**：投资人自述的对赌条款 ｜ 创始人为拿救命资金做出的实质性妥协 ｜ 公司最狼狈时期的内部状况回忆。**只记录投资人自述，不判断其对错。**

## 三、产品（具体产品）

### 维度二：产品演进与 PMF 生长线（Product Evolution & PMF）

**目标**：还原从粗糙 MVP 到杀手级产品的完整异变轨迹。

**信源**：App Annie/Sensor Tower/点点数据的历史 Changelog 与绝版截图 ｜ Wayback Machine 1.0 时代 UI ｜ 早期垂直社区推广帖（Product Hunt/V2EX/贴吧，创始人自己发的"我们做了一款小工具"）｜ 百度指数/Google Trends/微信指数历史曲线 ｜ 黑猫投诉/App Store 差评。

**检索语法**：

```
"产品名" after:YYYY-MM-DD before:YYYY-MM-DD   ← 锁定指数波峰年月，倒查那几个月产品做了什么
```

**微观打法三个采集点**：

1. **MVP 寒酸样貌**：1.0 的 UI 截图、早期更新日志、第一条推广帖。→ 伟大产品诞生时往往简陋甚至被群嘲；找到最初切入的微小痛点。
2. **PMF 齿轮咬合的精确瞬间**：指数暴涨波峰 → 倒查那一周/月里的反常识改动（砍掉 80% 功能/改收费模式/某圈层偶然爆红）。→ 这是商业纪录片最肾上腺素飙升的"物理转折"，**波峰年月+同期动作+来源**三者必须齐。
3. **隐形手铐（转换成本）**：差评与客诉（"难用却离不开"）。→ 夸产品的都是虚的，骂着却离不开的痛苦才是高转换成本。**只摘录原话与数据，不总结护城河结论**（结论归 fenxi）。

## 四、公司/关卡

### 维度三：竞争对手审计（Competitor Adversarial Audit）

**目标**：竞品扒出的产品缺陷、供应链猫腻、渠道库存证据——用于交叉验证财报真实性。

**信源**：竞品公开反向白皮书与发布会指控 ｜ 骂战记录 ｜ 企查查/裁判文书网中的知识产权与不正当竞争诉讼。

**采集点**：公开指控原文+出处 ｜ 诉讼案由与判决结果 ｜ 渠道库存/供应链证据。只采集，不裁决谁对谁错。

### 关卡流司法与披露证据库（司法工商历史证据）

**目标**：找回被公关掩盖的死穴、股权纠纷、资金链断裂前夜。

**信源与动作**：

- **企查查/天眼查/启信宝**：重点看"历史被执行人""股权冻结记录""裁判文书"。
- **裁判文书网/企查查法律诉讼页**：搜公司与早期联合创始人、供应商、投资人的合同纠纷。→ 真相常藏在判决书"**本院查明**"部分——最真实的对赌协议、现金流断裂时间点、密室协议。
- **招股书披露（三套，按上市地选用——修正早期材料"一律 SEC"的硬伤）**：
  - 港股 → 招股书"History and Corporate Structure（历史及公司架构）"与"Risk Factors（风险因素）"章
  - A 股 → 招股说明书"发行人基本情况/诉讼仲裁"披露
  - 美股 → SEC S-1/10-K 的 Business/Risk Factors/Legal Proceedings
  - 公司必须向交易所坦白曾发生的法律纠纷与重组——**这是无法公关掉的铁证**。未上市公司标「暂缺」。
- **对抗性特稿**：《晚点 LatePost》《财新》《第一财经周刊》《WSJ》《Bloomberg Businessweek》《The Information》深访。

```
"公司名" AND ("危机" OR "内幕" OR "独家" OR "对赌" OR "近身肉搏" OR "纠纷")
```

### 维度五 a：空方证据包（只采集，不推导）

**目标**：为 fenxi 的 C 闸门空方压力测试备料。**本层只收弹药，不开枪**——Kill_Thesis 推导（维度五 b）归 yt-fenxi。

**信源与采集点**：

- **做空机构报告**：Hindenburg / Muddy Waters / GMT Research / Culper Research 针对标的（或同行）的报告——审计逻辑（访谈经销商/核对发票）+核心指控+标方回应，**双方都要**。
- **财报附注三项**：应收账款账龄（增速远超营收增速=压货信号）、存货减值准备、关联方交易。只抄数字+出处，不下"PMF 失效"结论。
- **券商多空对抗**：Sell 评级/买方基金离场调仓的推演逻辑，整理他们认为模式不可持续的底层假设（注明是谁的观点）。

## 五、交付：候选锚点清单（报告 §5.4）

拆局类选题交付时，除六章+附录外，必须在报告 §5.4 附**候选锚点清单**——供 yt-fenxi N6 切入瞬间穷举消费：

- **物件锚点**：可物理呈现的具体实物（一台样机/一份判决书/一张旧截图）
- **数字锚点**：具体数字（账上只够发一个月工资/72 小时/蒸发 3 万亿）
- **对话锚点**：原话引用（内部信一句/法庭陈述一句/早年论坛帖子一句）

**纪律**：三类各报 ≥1 个候选（出处+关联素材索引必填）；确实挖不到某类→标「暂缺」+原因，**不硬凑**（继承不编造铁律）。只盘点不评估——哪个锚点能当切入瞬间、过 4C 过滤，是 fenxi 的活。

## 六、与现有流程的接口

1. **步骤 5 子 Agent 组织**：四路并行子 Agent 是"运输层"不变；本手册是"内容地图"——给各子 Agent 分派手册对应模块的检索词与信源清单（如：中文社媒 Agent 领维度一语法，官方/深度 Agent 领司法披露+空方，视频 Agent 不变）。
2. **报告归位映射**（挖到的料进哪章，骨架不增不减）：
   - 维度一/四 → §二（时间线/事实）+ §3.2-3.4（观点条目）
   - 维度二 → §二 + §4.3（关键证据摘录）
   - 维度三 + 司法披露 → §二 + §3.5（争议点配对原料）+ §4.4（矛盾信息）
   - 维度五 a → §3.3（质疑方条目）+ §4.4，标注"空方证据"
   - 候选锚点 → §5.4
3. **降级态**：OpenCLI 不可用时，Wayback/裁判文书/招股书等可 WebFetch 直达的信源照常挖；登录墙（脉脉/Glassdoor）计入 skipped[]，对应锚点标「暂缺」——照实交付，不编造补齐。
4. **禁区重申**：本手册任何"为什么"都只是解释采集方向（内部工作语言），**不得写入报告正文**；报告正文只有证据+出处+双方主张。
