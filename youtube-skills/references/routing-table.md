# 意图 → 技能路由表（细表）

> SKILL.md「执行流程 步骤 2」的细化。core 识别意图后先查本表，再读池状态复核。
> 冲突时的裁决顺序：**用户显式指名技能 > 池状态机 > 本表**。

## 用户说什么 → 谁接

| 用户意图（例句） | 路由到 | 备注 |
|---|---|---|
| "初始化 / 装好了吗 / 配置工作区" | youtube-skills 自身 | 步骤 1 初始化 + skills 检测 |
| "推进选题 X / X 下一步做什么" | 读池 → route 映射 | core 本行 |
| "搜集 X 的资料 / 补采 X" | yt-ziliao | 池状态应为阶段二未就绪 |
| "分析 X / 评估这个选题" | yt-fenxi | 池状态=阶段二就绪（有链接+完整度≥60），否则先 ziliao |
| "给 X 写脚本 / 出脚本" | yt-jiaoben | 前置：池状态=阶段三（已过 N8）；缺分析卡走 Step 0.5 |
| "定稿 / 审脚本" | 人（硬闸门③） | jiaoben 交付后 core 只提醒，不代审 |
| "看看数据 / 复盘 X" | fupan [待开工] | 技能未建，提示人工 |
| "改方向 / 角度不对" | 回 yt-fenxi N6 | 回环入口，不算新选题 |
| "换主体深挖"（如 China GT 赛事→运营公司） | yt-fenxi N1 选题精化 | 主体锁死在 N1，之后改方向不换主体 |

## 状态与意图打架时

| 场景 | 处置 |
|---|---|
| 用户说"分析 X"但池状态=阶段一（未立项） | 提示"未过立项闸门①"；人坚持则视同立项拍板，先迁状态再 ziliao→fenxi |
| 用户说"写脚本"但状态=阶段二 | 缺分析卡，先路由 fenxi；**禁止跳段** |
| 用户说"分析"但资料未就绪 | 先 yt-ziliao 补采（N2b 规则同），就绪后自然回到 fenxi |
| 池状态为空/未登记 | 未知状态不硬跑，请人确认实际阶段 |
