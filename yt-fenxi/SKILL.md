# yt-fenxi 选题分析

## 概述

对选题池内**单个选题**做深度分析：环境自检与初始化 → 穷举切入角度 → 事实核验三分 → C 分层闸门 → 产出分析卡 → 人拍板 → 状态迁移。

四条核心原则：

1. **客观而非主观**——立项判断只依据可外化核验的硬条件（信源数、合规、反常识点），不依赖"感觉不错"。
2. **防编造靠机器不靠自觉**——分析卡交付前必须过无出处断言扫描（`scripts/scan_unsourced.py`），扫描不过退回核验。
3. **机器管流量，人管判断**——全流程唯一硬闸门是人审（做/改方向/不做），机器不得替人拍板，也不得在缺料时硬跑。
4. **路径不硬编码**——池 token、表 ID、状态选项名全部来自 `config.yaml`（初始化问答生成，用户可手改），技能文件内不写死任何用户环境路径。分析卡路径=技能内 `workspace/<编号>/`，无需配置。

## 何时使用 / 不适用

| 场景 | 归属 |
|---|---|
| "分析这个选题" / "分析 T-2026-001" / 对池内某行要求深度评估 | ✅ 本技能 |
| 选题分析卡的复核、改方向重评 | ✅ 本技能（回环入口） |
| "检查环境" / 首次安装初始化 | ✅ 本技能（阶段 0，见执行流程） |
| "把池里 Top5 全分析了我挑一个"批量深评 | ❌ 不支持（Q3 拍板：一次一个全深评，防批量替代 tansuo 排序） |
| 发现新选题、雷达扫描、词库进化 | ❌ tansuo / radar-engine |
| 六章资料包采集 | ❌ yt-ziliao（本技能仅做就绪检查与自动补采调用） |
| 写脚本 | ❌ jiaoben-sop7（本技能的下游消费者） |

## 铁律（违反即返工）

- **禁止编造**任何事实、数据、引语、来源。无出处断言过不了 N7 扫描。
- **消费对账铁律**（2026-09-09 防偷懒机制）：yt-ziliao 交付的素材/争议/角度（manifest ID 集合）必须全量有去向——正文引用或「十一、消费对账」节销号（去向+一句话原因），**静默丢弃即返工**；manifest 经 `+fetch 01b-资料清单.md` 提取 JSON 落 `workspace/<编号>/manifest.json` 再喂 `scripts/audit_consumption.py`，exit 0 才准入 N8 人审。
- **不越权改上游**：不改 ziliao 的核验结论/立场标注；素材疑点进盲区清单回采，不自行重判。
- C 闸门四道硬条件**任一不过 → 不出分析卡**，直接建议不做并附理由（Q5：时效热点不豁免）。
- **禁止覆盖人填字段**——核心钩子、目标受众等已有内容绝不冲掉，空则填、不覆盖。
- 桥接调用失败**禁止自动重试**，按桥接文件降级备用通道。
- 缺失数据标「待补充」，禁止估算或编造补全。
- 状态迁移只写 config.yaml `state_options` 配置的四个值：`researching` / `confirmed` / `eliminated`（以及补采完成时的 `researching`），越权写 `阶段四：内容制作` 即违规。
- **禁止在技能文件内硬编码任何用户环境路径**——池 token、表 ID 一律读 `config.yaml`；分析卡=技能内 `workspace/<编号>/`（无需配置）；飞书目标文件夹=core 共享配置 `feishu_root_folder_token` + `<编号> <标题>/`。配置缺失走初始化问答，不猜默认。config 里的 token/ID 原样引用，**禁止缩写**（`DvQtb4…dnhc` 这种写法是事故源），格式速查见 `references/lark-field-formats.md`。
- **分析卡=工作区 md 主档 + 飞书 .md 副本，双写一主一副**（2026-09-10 存储重构，取代 2026-09-09"禁止建到飞书"旧条）：本地 `workspace/<编号>/analysis-card.md` 是唯一可编辑源（机器下游消费+版本演进）；定稿/修订后 `markdown +overwrite` 推飞书 `<编号> <标题>/02-分析卡.md`（N8 人审入口），URL 回填「分析卡链接」。改卡只改本地再重推，绝不在飞书文档直接改（防两端漂移）。资料报告归 yt-ziliao（含推 `01-资料报告.md`/`01b-资料清单.md`+回填「资料采集」），fenxi 不越权代建。边界：`报告=资料原料`（ziliao 产物），`卡=分析判断`（fenxi 产物）。
- **每次阶段跳转必须同步更新分析卡 YAML 的 `当前节点` 字段**；断点恢复只读卡续跑，不凭对话记忆续跑（压缩丢上下文后记忆不可信）。
- "改方向"= 对切入点穷举提反馈重跑 N6（Q2 拍板），**不是**改选题本身；换主体（如 China GT 从赛事本身换成运营公司）发生在 N1 触发时的选题精化，不算改方向。

## 执行流程

### 阶段 0/7：环境自检与初始化

每次触发"分析这个选题"时**静默**执行；用户主动说"检查环境"时执行并展示明细。运行 `scripts/preflight_check.py`，按返回 verdict 处置：

| verdict | 含义 | 处置 |
|---|---|---|
| `ok` | 全部通过 | 只向用户报一行"环境就绪"，直接进入阶段 2 |
| `degraded` | 有降级项 | **分级处置**：机评轻档 → 必须向用户打印一行「本次机评走轻档（原因），置信度 X」并**等确认**（轻档影响 C 闸门输入质量=影响立项判断）；其余降级项 → 打印告知即可继续，不阻塞 |
| `blocked` | 有阻断项 | **停下，走初始化问答**，完成生成/补齐 `config.yaml` 后重新自检，通过再继续 |

**初始化问答（仅 blocked 时走，或用户说"初始化"时走）**——一次问一轮，带默认值，用户直接回车即采纳默认：

1. 选题池在哪？→ 请用户提供飞书多维表格链接（解析出 base_token + table_id；不会解析就请用户从链接里复制）
2. 确认状态选项名 → 从池里读「选题状态」现有选项回填 `state_options`（用户改过的池不用手填）

问答结果写入 `config.yaml`（模板见 `config.template.yaml`），写完后**必须重跑 preflight_check.py 验证**，通过才进阶段 2。

**"检查环境"命令**：任何时候用户说"检查环境/自检"，完整展示 preflight_check.py 明细输出（--verbose），包括已通过的项。

### 阶段 2/7：触发与资料就绪

1. **读选题行**：经 lark-base 桥接（`references/lark-base-bridge.md`），用 `config.yaml` 的 base_token/table_id 按编号或标题定位记录。**读池纪律强制生效**（search/get 定位取数、list 分页 ≤10、输出管道截断）。入口状态必须是 `state_options.entry` 配置的选项（老新两版都认）；其他状态提示用户当前所处阶段，不重复分析。
2. **选题精化**（N1 规则）：若用户意图是深挖主体的另一面（如 China GT：从赛事本身 → 赛事运营公司），在触发时确认新主体，更新选题行标题与一句话描述后进入分析。**这一步完成即锁死主体**，之后"改方向"只换角度不换主体。
3. **资料就绪检查**（N2）：`资料采集` 字段有有效链接 且 `资料完整度 ≥ 60`？两个条件同时满足才算就绪。
   - 就绪后检查 **manifest.json**（路径 = youtube-skills core 共享配置 `dirs.reports` 下 `<编号>-manifest.json`）：存在 → N5 起对账的机械原料；缺失 → 打印一行警告，降级"文档 URL 抽取"模式（旧版报告兼容），**不阻断**。
4. **自动补采**（N2b，Q4 拍板不问人）：未就绪 → 调 yt-ziliao 桥接（`references/yt-ziliao-bridge.md`）补采六章资料包；状态迁 `阶段二：资料研究`。补采失败 → 报缺失清单并**终止**，不硬跑。

### 阶段 3/7：机评与 C 闸门

5. **机评**（N3）：拆局价值四维打分——按 yt-ziliao 挖掘手册-v2 三层×五维清点资料包证据 → 四维加权。权重 **非共识30 / 齿轮可还原30 / 决策考古25 / 关卡流15**（频道定位升级 vN6.0 换轴，锚点见 `references/scoring-anchors.md` §一）。原流量四维（Demand/Conflict/Outlier/Archive）降为**参考层**：仍评估附卡，不进总分不进闸门。
   - **默认重档**：参考层四维调 YouTube Data API 精算对标数据。
   - **降级轻档**：API 限流/不可用时参考层切 WebSearch 定性档 + 置信度标注（Q1 拍板）。降级必须做两件事：①向用户打印一行告知并**等确认**（除非用户本轮已明确"遇到限流直接轻档"）；②把降级原因自动写入分析卡 YAML 的 `degraded_reasons` 字段（不靠人记）。
6. **C 闸门**（N4）：硬条件逐项判定（✓/✗ 呈现，Q6 拍板）：
   - ① **三方对照可得**：创始人视角 + 至少一方反方视角（离职者/对手/投资人）有实料（vN6.0 由"硬核信源≥2"改造）
   - ② 合规：无敏感赛道风险（结论回写复用「有法律风险」字段逻辑）；同时输出**涉及敏感主体类型清单**（上市公司/法人/个人/官方声明引用方等），写入分析卡供下游法律预审标雷——fenxi 只标雷区，不排雷
   - ③ 获得感 ≥ 40：反常识点 ≥ 1 个（"原本以为…结果…"）
   - ④ **空方压力测试**（vN6.0 新增）：产出 ≥1 条具体 Kill_Thesis 草案——"若 3 年内市值蒸发 50% 的单点崩溃原因"，须有触发条件+崩溃路径+空方证据来源；空泛质疑（"竞争加剧"类无实据）= 不通过
   - 任一 ✗ → 不写分析卡，输出"建议不做 + 未过项 + 理由"，状态迁 `已淘汰`，流程结束。

### 阶段 4/7：事实核验

7. **核验三分**（N5，独立 pass，不与切入点分析混合）：
   - 按五分类提取可验证主张：事实断言 / 统计数字 / 归属引语 / 定义 / 历史声明。
   - 三分：**已证实**（≥2 独立源）/ **待验证**（SIFT 四步后仍冲突，冲突证据必须保持可见）/ **观点**（标注归属方）。
   - 无源主张进盲区清单 + 补采建议。
7.5. **核心争议点提炼**（N5.5）：消费 yt-ziliao 报告 3.5 争议点原料清单，选定 1-3 个本期主争议点，逐项填：我们站哪边 + 依据（限 N5 已证实事实/转述，禁止无中生有）+ 在四幕中的引爆位置（承/转/合）。争议点是故事引擎，供下游 yt-jiaoben 元数据头「核心争议点」与观点层站队使用。本节与 N5 待验证表分工：N5 管"真相没查清"，N5.5 管"真相各自已清但立场对立"。

### 阶段 5/7：切入点穷举

8. **穷举排序**（N6，本技能第一核心价值，2026-09-09 深度化升级）：
   - **四维视角层穷举清单**：每个角度必须归属一个视角层，四层每层 ≥1 个角度，总计 5-8 个：
     - ① 当下反应层——事故当下 / 舆论反馈（例：起火事故责任链）
     - ② 历史脉络层——主体发展史 / 创办人决策史（例：赛事十年兴衰史）
     - ③ 主体架构层——股权结构 / 商业模型（例：运营公司空壳链）
     - ④ 行业格局层——同类对比 / 国际对标 / 格局参照（例：与国际 GT 赛事对比）
     某层确实挖不出角度时**必须在卡里写明空缺原因**（如"成立不足两年，无史可考"），禁止为凑数编造历史角度。
   - **四维度加权排序**：**空白度 30%**（对标池谁讲过谁没讲，须点名证据）/ **凭证密度 25%**（资料包硬事实计数）/ **反常识强度 25%**（"原本以为…结果…"点数）/ **深度揭示力 20%**（潜力分定义见 `references/scoring-anchors.md`——角度做透了能否讲清主体"怎么走到今天"，惩罚"只回答主体是谁"的空壳型角度）。每个角度附：差异点 / 优势 / 劣势 / **视角层标签**。
   - **分桶保留功能分法**（Quick Wins=快见效 / Strategic Builds=需补采 / Long-term=条件未熟）；"历史脉络型角度被显式看见"靠视角层标签实现，桶名不改。
   - **切入瞬间穷举（N6 第 5 维，vN6.0 新增）**：消费 ziliao §5.4 候选锚点清单 → 按三锚点（物件/数字/对话）补挖候选 → 每个候选过 Nieman 4C（Concrete/Conflict/Consequence/Core Theme）→ 通过者标切入时机矩阵类型（Crisis/Pivot-MVP/Genesis/Peak，买方视角推荐 Pivot-MVP）→ 交 N8 人审人选。纪律见 `references/scoring-anchors.md` §4.4。

### 阶段 6/7：组装与扫描

9. **组装分析卡**：按 `references/analysis-card-template.md` 模板写入分析卡文件（路径规则见下「数据契约」）。
10. **无出处扫描**：跑 `scripts/scan_unsourced.py <分析卡路径>`。发现无出处断言/引语/统计 → 回阶段 3 补凭证后重扫，直到通过。
10.5. **消费对账扫描**（2026-09-09 防偷懒闸门）：跑 `scripts/audit_consumption.py <manifest.json> <分析卡路径>`（manifest 缺失时退化为从报告 6.1 抽 URL 的降级模式）。exit 1 → 按差集清单回 N5/N5.5/N6 补"引用或销号"后重扫，直到 exit 0——**无出处扫描管"写进卡的都要有源"，对账扫描管"报告里的都要有着落"，两闸缺一不可**。

### 阶段 7/7：人审与迁移

11. **人审**（N8，唯一硬闸门）：展示分析卡要点 + 阻塞提示模板，等用户明确拍板。禁止替用户默认"做"。
12. **迁移**（N9）：
    - **做** → 状态迁 `阶段三：确认选题`；回写 `核心钩子`、`目标受众`、**`分析卡链接`（飞书文档 URL）**（**空则填、不覆盖**）；给 `优先级` 建议供人调整；选定的切入角度浓缩写入 `切入视角`（现有选项）或并入核心钩子。
    - **不做** → 状态迁 `已淘汰`；理由写入分析卡，同时若 `复盘笔记` 为空可填入一行淘汰理由。
    - **改方向** → 按反馈回阶段 4 重跑 N6。

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 资料完整度 55 也硬跑分析 | N2 未就绪 → 先补采；补采失败即终止，报缺失清单 |
| C 闸门①只有创始人官方叙事一方但"题材很炸"照样出卡 | 硬条件一票否决：三方对照（创始人+至少一方反方视角）是 vN6.0 后的①号线，题材炸是机评非共识分的事，救不了闸门 |
| 空方压力测试写"竞争加剧行业不景气"糊弄 | 条件④要具体 Kill_Thesis：触发条件+崩溃路径+空方证据来源，空泛质疑=不通过 |
| 切入瞬间候选不过 4C 也硬塞给人审 | 4C 缺一不可，全不过就写"本期无合格切入瞬间"建议补采或不做（scoring-anchors §4.4 纪律） |
| 机评限流后跳过机评直接写卡 | 降级轻档并标注，机评不可省——C 闸门④空方压力测试依赖主评分轴输出 |
| 穷举 3 个角度就收工 | 5-8 个是下限，角度少于 5 说明穷举不充分，继续挖 |
| 用 record-list 全量拉池再人肉翻目标行 | 读池纪律：search/get 定位，list 必分页 ≤10，输出管道截断——全量一次几万 token，直接吃爆上下文（9/9 事故） |
| 分析卡引了数据但没说哪来的 | 扫描会拦；每个统计数字/引语旁必须有信源名 |
| 人审没回复就默认"做"推进 | 硬闸门，无明确回复即阻塞，重新展示 checklist |
| 迁移时把用户已写的核心钩子覆盖了 | 空则填、不覆盖；已有内容只在用户明确要求时改 |
| 分析前用户口头给了钩子/受众素材 | 记入分析卡「七、建议」节；N9 回填时仍守"空则填、不覆盖"，用户素材不抢跑 |
| preflight 报 degraded 就静默往下跑 | 分级处置：机评轻档必须告知+等确认；其余降级项至少打印一行告知 |
| 把分析卡当资料报告建到飞书文档 | 卡=本地 markdown；要落飞书的报告是 yt-ziliao 的产物，越权即违规 |
| 素材挑顺手的用、其余静默丢弃 | 消费对账闸会拦：每条素材必须"引用或销号"，差集为零才准入 N8 |
| 凭印象判断"报告内容都用上了" | 只认 audit_consumption.py 输出；manifest 缺失也要跑降级模式（URL 抽取） |
| config 里的 token 抄成缩写（如 `DvQtb4…dnhc`） | 一律从 config.yaml 原样复制全文；缩写 token 是 400 错误事故源 |
