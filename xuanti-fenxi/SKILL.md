# xuanti-fenxi 选题分析

## 概述

对选题池内**单个选题**做深度分析：穷举切入角度 → 事实核验三分 → C 分层闸门 → 产出分析卡 → 人拍板 → 状态迁移。

三条核心原则：

1. **客观而非主观**——立项判断只依据可外化核验的硬条件（信源数、合规、反常识点），不依赖"感觉不错"。
2. **防编造靠机器不靠自觉**——分析卡交付前必须过无出处断言扫描（`scripts/scan_unsourced.py`），扫描不过退回核验。
3. **机器管流量，人管判断**——全流程唯一硬闸门是人审（做/改方向/不做），机器不得替人拍板，也不得在缺料时硬跑。

## 何时使用 / 不适用

| 场景 | 归属 |
|---|---|
| "分析这个选题" / "分析 T-2026-001" / 对池内某行要求深度评估 | ✅ 本技能 |
| 选题分析卡的复核、改方向重评 | ✅ 本技能（回环入口） |
| "把池里 Top5 全分析了我挑一个"批量深评 | ❌ 不支持（Q3 拍板：一次一个全深评，防批量替代 tansuo 排序） |
| 发现新选题、雷达扫描、词库进化 | ❌ tansuo / radar-engine |
| 六章资料包采集 | ❌ ziliaocaiji（本技能仅做就绪检查与自动补采调用） |
| 写脚本 | ❌ jiaoben-sop7（本技能的下游消费者） |

## 铁律（违反即返工）

- **禁止编造**任何事实、数据、引语、来源。无出处断言过不了 N7 扫描。
- C 闸门三道硬条件**任一不过 → 不出分析卡**，直接建议不做并附理由（Q5：时效热点不豁免）。
- **禁止覆盖人填字段**——核心钩子、目标受众等已有内容绝不冲掉，空则填、不覆盖。
- 桥接调用失败**禁止自动重试**，按桥接文件降级备用通道。
- 缺失数据标「待补充」，禁止估算或编造补全。
- 状态迁移只写本技能有权写的三个值：`阶段二：资料研究` / `阶段三：确认选题` / `已淘汰`，越权写 `阶段四：内容制作` 即违规。
- "改方向"= 对切入点穷举提反馈重跑 N6（Q2 拍板），**不是**改选题本身；换主体（如 China GT 从赛事本身换成运营公司）发生在 N1 触发时的选题精化，不算改方向。

## Progress

被单独调用时，先输出阶段定位句，再展示 micro-checklist；每次阶段跳转、硬闸门、会话恢复都必须重新渲染。进度持久化：分析卡文件头记录当前节点，中断后读取恢复。

```markdown
选题分析进度（选题编号 T-XXXX-XXX）
阶段 1/6：触发与资料就绪
- [ ] Step 1 读选题行+选题精化确认 [需确认]
- [ ] Step 2 资料就绪检查 [自动]
- [ ] Step 3 调 ziliaocaiji 补采（仅缺失时） [自动]
阶段 2/6：机评与 C 闸门
- [ ] Step 4 动态评估法机评（默认重档） [自动]
- [ ] Step 5 C 闸门三条件逐项判定 [自动]
阶段 3/6：事实核验
- [ ] Step 6 五分类提取+三分+SIFT [自动]
阶段 4/6：切入点穷举
- [ ] Step 7 穷举 5-8 角度+三维排序+分桶 [自动]
阶段 5/6：组装与扫描
- [ ] Step 8 组装分析卡+无出处扫描 [自动]
阶段 6/6：人审与迁移
- [ ] Step 9 人审拍板：做/改方向/不做 [硬闸门] [可回环]
- [ ] Step 10 状态迁移+字段回填 [自动]
```

**阻塞提示模板**：

```markdown
⚠️ 当前阻塞：等待你拍板（阶段 6/6 Step 9）
你可以：
- 回复"做 + 选第 N 个角度"→ 立项，状态迁「阶段三：确认选题」
- 回复"改方向 + 说明"→ 回退阶段 4 重跑穷举
- 回复"不做 + 理由(可选)"→ 状态迁「已淘汰」
```

**回环映射**："改方向" → 阶段 4 Step 7；"扫描发现编造" → 阶段 3 Step 6；"补采后资料仍不足" → 终止并报缺失清单。

## 执行流程

### 阶段 1/6：触发与资料就绪

1. **读选题行**：经 lark-base 桥接（`references/lark-base-bridge.md`）按编号或标题定位记录。入口状态必须是 `阶段一：想法记录` 或 `想法记录`（老选项）；其他状态提示用户当前所处阶段，不重复分析。
2. **选题精化**（N1 规则）：若用户意图是深挖主体的另一面（如 China GT：从赛事本身 → 赛事运营公司），在触发时确认新主体，更新选题行标题与一句话描述后进入分析。**这一步完成即锁死主体**，之后"改方向"只换角度不换主体。
3. **资料就绪检查**（N2）：`资料采集` 字段有有效链接 且 `资料完整度 ≥ 60`？两个条件同时满足才算就绪。
4. **自动补采**（N2b，Q4 拍板不问人）：未就绪 → 调 ziliaocaiji 桥接（`references/ziliaocaiji-bridge.md`）补采六章资料包；状态迁 `阶段二：资料研究`。补采失败 → 报缺失清单并**终止**，不硬跑。

### 阶段 2/6：机评与 C 闸门

5. **机评**（N3）：动态评估法四维打分——语义解析扩词（实体还原+消歧）→ 对标池 → 离群倍率+反作弊 → 四维加权。权重 Demand25 / Conflict30 / Outlier20 / Archive25。评分锚点见 `references/scoring-anchors.md`。
   - **默认重档**：调 YouTube Data API 精算对标数据。
   - **降级轻档**：API 限流/不可用时切 WebSearch 定性档 + 置信度标注（Q1 拍板）。降级必须在分析卡标注"本次机评为轻档"。
6. **C 闸门**（N4）：硬条件逐项判定（✓/✗ 呈现，Q6 拍板）：
   - ① Archive ≥ 2 项硬核信源（工商/司法/深度报道级）
   - ② 合规：无敏感赛道风险（结论回写复用「有法律风险」字段逻辑）
   - ③ 获得感 ≥ 40：反常识点 ≥ 1 个（"原本以为…结果…"）
   - 任一 ✗ → 不写分析卡，输出"建议不做 + 未过项 + 理由"，状态迁 `已淘汰`，流程结束。

### 阶段 3/6：事实核验

7. **核验三分**（N5，独立 pass，不与切入点分析混合）：
   - 按五分类提取可验证主张：事实断言 / 统计数字 / 归属引语 / 定义 / 历史声明。
   - 三分：**已证实**（≥2 独立源）/ **待验证**（SIFT 四步后仍冲突，冲突证据必须保持可见）/ **观点**（标注归属方）。
   - 无源主张进盲区清单 + 补采建议。

### 阶段 4/6：切入点穷举

8. **穷举排序**（N6，本技能第一核心价值）：
   - 穷举 5-8 个切入角度，每个角度附：差异点 / 优势 / 劣势。
   - 三维度加权排序：**空白度 40%**（对标池谁讲过谁没讲，须点名证据）/ **凭证密度 30%**（资料包硬事实计数）/ **反常识强度 30%**（"原本以为…结果…"点数）。
   - 分桶：Quick Wins / Strategic Builds / Long-term。

### 阶段 5/6：组装与扫描

9. **组装分析卡**：按 `references/analysis-card-template.md` 模板写入分析卡文件（路径规则见下「数据契约」）。
10. **无出处扫描**：跑 `scripts/scan_unsourced.py <分析卡路径>`。发现无出处断言/引语/统计 → 回阶段 3 补凭证后重扫，直到通过。

### 阶段 6/6：人审与迁移

11. **人审**（N8，唯一硬闸门）：展示分析卡要点 + 阻塞提示模板，等用户明确拍板。禁止替用户默认"做"。
12. **迁移**（N9）：
    - **做** → 状态迁 `阶段三：确认选题`；回写 `核心钩子`、`目标受众`（**空则填、不覆盖**）；给 `优先级` 建议供人调整；选定的切入角度浓缩写入 `切入视角`（现有选项）或并入核心钩子。
    - **不做** → 状态迁 `已淘汰`；理由写入分析卡，同时若 `复盘笔记` 为空可填入一行淘汰理由。
    - **改方向** → 按反馈回阶段 4 重跑 N6。

## 数据契约

| 项 | 约定 |
|---|---|
| 选题池 | 飞书多维表格「选题表」，经 lark-base 桥接读写；36 字段含义与 fenxi 使用规则见 `references/pool-field-map.md` |
| 分析卡路径 | `~/Documents/YouTuber工作流/选题分析卡/<选题编号>-<选题标题>.md`（无编号用标题缩写） |
| 淘汰卡归档 | 同目录 `archive/已淘汰/` 子目录，不删除（KW-06 统计需要留痕） |
| 机评分 | **只存分析卡，不进飞书表**（拍板决定 #2）；表内分数相关仅人工维护的 `优先级` |
| 穷举结果 | **只存分析卡**（拍板决定 #3）；表内只回填人拍板后的最终角度 |
| 合规检查 | 复用 `有法律风险` checkbox（拍板决定 #4），不新建字段 |

## 常见错误

| 错误 | 正确做法 |
|---|---|
| 资料完整度 55 也硬跑分析 | N2 未就绪 → 先补采；补采失败即终止，报缺失清单 |
| C 闸门 Archive 只 1 个信源但"题材很炸"照样出卡 | 硬条件一票否决，题材炸是机评 Conflict 分的事，救不了 Archive |
| 机评限流后跳过机评直接写卡 | 降级轻档并标注，机评不可省——闸门③依赖它 |
| 穷举 3 个角度就收工 | 5-8 个是下限，角度少于 5 说明穷举不充分，继续挖 |
| 分析卡引了数据但没说哪来的 | 扫描会拦；每个统计数字/引语旁必须有信源名 |
| 人审没回复就默认"做"推进 | 硬闸门，无明确回复即阻塞，重新展示 checklist |
| 迁移时把用户已写的核心钩子覆盖了 | 空则填、不覆盖；已有内容只在用户明确要求时改 |
| 分析前用户口头给了钩子/受众素材 | 记入分析卡「七、建议」节；N9 回填时仍守"空则填、不覆盖"，用户素材不抢跑 |
